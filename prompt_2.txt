[후반전: AI 드림팀 원탁회의]
[Role & Context] 너는 최고 수준의 MLOps 엔지니어이자 LangGraph 기반의 LLM Multi-Agent 아키텍트야. 우리는 SSTR2 타겟 방사성의약품을 설계하기 위해 5명의 AI 전문가가 실시간으로 협업하는 'AI Scientist 드림팀' 시스템의 후반전(Phase 2)을 구축하고 있어. 너는 전반전에서 넘어온 1만 개의 후보 물질(SSTR2_Filtered_10K.csv)을 처리하는 대리 모델(Surrogate) 학습 모듈과 5인 에이전트 협업 시스템을 작성해야 해.

[The 3 Ultimate Success Metrics] 모든 시스템 로직과 에이전트의 판단 기준은 반드시 아래 3가지 수치를 달성하는 데 초점이 맞춰져야 해: 1. 정밀타격 (Selectivity): 정상 세포(SSTR1, 3, 4, 5) 대비 SSTR2 표적에 100배 이상 강력하게 결합할 것. 2. 생존력 (Retention): 암세포 표적 결합 후 최소 72시간(3일) 동안 절대 떨어지지 않고 유지될 것. 3. 안전성 (Therapeutic Index): 종양 대 신장의 방사선 비율을 기존 대조군(Dotatate) 대비 최소 20% 이상 개선하여 신장을 보호할 것.

[Task 1: Module 02. 02_train_surrogate.py (AI 대리 모델)]
- 기능: 1만 개의 데이터 중 일부를 정밀 도킹하여 ESM-2 임베딩 + XGBoost 모델을 학습시키고, 나머지 서열의 결합력을 초고속으로 예측하여 상위 100개를 추출함.
- 핵심 로직: > * 대조군(Dotatate)의 결합 에너지를 Baseline으로 설정. * SSTR2 결합력뿐만 아니라 비표적 수용체에 대한 **선택성(Selectivity)**을 가검증하여 '정밀타격 100배' 가능성이 높은 서열을 우선 선발.
- Output: SSTR2_Top100_Boardroom_Ready.csv

[Task 2: Module 03. 03_ai_boardroom.py (5인 AI 드림팀 협업)]
- Framework: LangGraph를 사용하여 에이전트 간의 상태(State)를 관리하고, **Ollama(기본값: llama3)*를 로컬 LLM 백엔드로 사용.
 Agent Configuration (MCP 방식의 공동 작업 노트 활용 ): 1. 증거 큐레이터: 논문 및 구조 데이터를 바탕으로 지식 기반 제공. 2. 설계 생성기: 기존 구조를 비틀어 창의적인 분자 설계도 제안 및 반려 시 재설계. 3. 구조 분석가 (성공 지표 ①, ② 검토): 3D 도킹 및 MD 시뮬레이션 관점에서 결합력과 72시간 체류 가능성을 정밀 평가. 4. PK 전문가 (성공 지표 ③ 검토): 체내 독성 및 신장 배설률을 검토하여 신장 안전성 20% 개선 여부 심사. 5. 실험 계획가: 최종 후보에 대한 방사성 물질 부착 전략 및 실제 실험 계획서 작성.
- Agent별 시스템 프롬프트(System Prompt) 세부 지침 (코드에 반드시 하드코딩할 것):
1. 증거 큐레이터 (Evidence Curator): "너는 수만 건의 단백질 구조와 논문을 바탕으로 팀에 지식을 제공한다. 타겟 서열이 기존 논문의 'Trp-Lys(마스터키)' 결합 메커니즘을 잘 따르고 있는지 PDB 데이터를 기반으로 레퍼런스를 제시하라."
2. 구조 및 친화도 분석가 (Structure Analyst): "너는 물리/구조 전문가다. **[성공 지표 1: 100배 정밀타격]**과 **[성공 지표 2: 72시간 생존력]**을 검증하라. 도킹 에너지가 SSTR2에 압도적인지 확인하고, 분자동역학 관점에서 해리 속도($k_{off}$)가 매우 낮아 72시간 이상 표적에 체류할 수 있는 단단한 구조(예: 베타 턴 유지)인지 심사하라. 기준 미달 시 설계 생성기에게 반려(Reject)하라."
3. 약물동태(PK) 전문가 (PK Expert): "너는 현실성 및 독성 전문가다. 전반전에서 넘어온 전하량/친수성 데이터를 분석하여 **[성공 지표 3: 신장 방사선 비율 20% 개선]**을 검증하라. 신장에 축적될 양전하 요소를 지적하고 독성 위험이 있으면 가차 없이 탈락시켜라."
4. 설계 생성기 (Design Generator): "너는 아이디어 뱅크다. 구조 분석가나 PK 전문가가 서열을 반려(Reject)할 경우, 핵심 뼈대(Cys 고리, FWKT)는 유지한 채 주변부 아미노산을 미세 변이(Mutation)시켜 지표를 통과할 수 있는 새로운 대안 서열을 즉각 제안하라."
5. 실험 계획가 (Experiment Planner): "최종 합격한 서열들에 대해, 방사성 물질(DOTA)을 N-term에 부착하는 방사화학적 합성 전략과, 실제 동물 모델(In vivo)에서 72시간 생존력 및 신장 독성 20% 개선을 어떻게 교차 검증할지 최종 실험 계획서를 작성하라."
- 소통(Graph) 방식: 각 에이전트는 서로의 피드백을 받아 상태(State)를 업데이트하는 순환 구조(Cyclic Graph)를 가짐. 평가 통과 $\rightarrow$ 실험 계획가로 이동, 평가 실패 $\rightarrow$ 설계 생성기로 돌아가 재설계 후 재평가.
- 출력물: 에이전트들의 치열한 토론 내용이 담긴 Boardroom_Transcript.log 파일과 최종 계획서 Final_Winning_Peptides_Report.md.

[Technical Requirements]
1. Local & Free: 외부 유료 API 없이 로컬 Ollama 환경에서 구동될 것. 모델명은 config.py에서 유연하게 변경 가능해야 함.
2. State Management: LangGraph의 StateGraph를 활용해 에이전트들이 평가 결과를 공유하고, 기준 미달 시 설계 생성기로 돌아가는 피드백 루프를 구현할 것.
3. Documentation: > * README.md에 Ollama 설치 및 llama3 모델 로드 방법 안내.
- Conda 환경 구축 및 pip install -r requirements.txt 명령어 포함.
- 5명의 에이전트가 어떻게 3대 지표를 검증하는지 상세 설명.
